# Правила взаимодействия ролей

## Общая база

Для дизайна используется один актуальный брендбук. Для структуры — одна карта услуг, категорий и адресов. Для общих блоков — согласованные исходники с версиями и перечнем страниц-потребителей.

История чата помогает восстановить причины решений. Итоговые правила и актуальные файлы должны быть доступны без повторного чтения всей истории.

## Границы ответственности

Чат страницы отвечает за свою страницу. Изменение общего дизайна, дерева или поведения сквозного блока оформляется как отдельная зависимость и передаётся владельцу соответствующей области.

При работе нескольких исполнителей один общий файл в каждый момент изменяет назначенный владелец. Остальные передают предложения, чтобы не перезаписывать результаты друг друга.

## Изменение общего блока

1. Указать причину изменения и затронутую версию.
2. Подготовить новую версию и проверить её отдельно.
3. Перечислить страницы, использующие блок.
4. Применить обновление и записать статус каждой установки.
5. Проверить результат на страницах.

Для Тильды учитывать отдельно глобальные подключения и копии кода в T123. Единый исходник не гарантирует единую версию всех установок.

## Статусы результата

| Статус | Что подтверждено |
| --- | --- |
| Прототип | Есть локальный результат для просмотра |
| Сохранено в редакторе | Изменение сохранено и проверено после повторного открытия |
| Опубликовано | Выполнена публикация |
| Проверено после публикации | Работа результата проверена на опубликованной странице |

Для формы проверка включает фактическую доставку заявки и обработку ошибок. Для страницы — содержание, адреса, мобильное отображение и взаимодействия.

## Незакрытые вопросы

- Подтвердить отдельного владельца структуры.
- Подтвердить владельца формы отправки.
- Разделить ответственность за шаблон страницы кейса и общий блок карточек кейсов.
- Сверить актуальные версии блоков и места их хранения.
- Завершить пилот и записать фактические измерения.
